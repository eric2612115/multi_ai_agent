# AI知识森林系统概述

## 系统简介

AI知识森林是一个基于对话内容自动构建知识图谱的系统，具有自我进化和自主反思能力。它能从用户与AI的对话中提取重要概念和关系，构建结构化的知识图谱，并通过自主反思循环优化知识结构，实现知识的有机生长和自然演化。

## 核心特性

1. **自动知识提取与放置**
   - 从对话中智能识别关键概念、实体和关系
   - 基于相似度和语义关系决定知识放置位置
   - 维护结构化的知识图谱

2. **自主反思系统**
   - 基于OODA循环(观察-定向-决策-行动)的自我评估和优化
   - 定期分析知识结构，识别缺口和不平衡
   - 自动执行优化任务改进知识结构

3. **知识生命周期管理**
   - 管理节点的状态转换：萌芽→成长→成熟→演化→衰退→休眠→归档
   - 重要且活跃的知识保持在前台，不重要的知识逐渐淡出
   - 实现记忆与遗忘的平衡，避免知识过载

4. **多层次抽象机制**
   - 从具体实例生成更高层次的抽象概念
   - 构建从实例到范式的多层知识结构
   - 支持知识压缩和泛化

5. **能量系统资源管理**
   - 模拟生物系统的能量代谢，合理分配计算资源
   - 在不同功能模块间智能分配"能量"资源
   - 确保系统高效运作，避免资源浪费

6. **概念创新机制**
   - 通过类比、整合、转化等方式合成新概念
   - 多种创新策略：类比合成、整合合成、转化创新、辩证合成
   - 通过创新扩展知识结构

7. **自我平衡机制**
   - 主题平衡调节，避免知识不平衡
   - 增长速率控制，保持稳定发展
   - 连接密度调节，优化知识网络

8. **主动知识获取**
   - 识别知识缺口并主动获取相关知识
   - 从多种外部源获取信息
   - 集成到现有知识结构中

## 系统架构

### 核心组件

1. **知识提取与放置系统**
   - `KnowledgeExtractor`: 从文本中提取实体、关系和向量
   - `KnowledgePlacementService`: 决定知识放置位置
   - 位置: `src/forest/extraction.py`, `src/forest/placement.py`

2. **知识图谱管理系统**
   - `KnowledgeGraphManager`: 管理图谱的CRUD操作
   - 位置: `src/forest/graph.py`

3. **反思系统**
   - `ReflectionSystem`: 协调完整的反思循环
   - `SystemObserver`: 收集系统状态指标
   - `KnowledgeAnalyzer`: 分析知识结构
   - `TaskExecutor`: 执行优化任务
   - 位置: `src/forest/reflection/`目录

4. **生命周期管理系统**
   - `LifecycleManager`: 管理节点状态转换
   - `StateTransitionEngine`: 控制状态转换规则
   - 位置: `src/forest/lifecycle/manager_combined.py`

5. **能量系统**
   - `EnergyManager`: 管理能量分配和消耗
   - 位置: `src/forest/energy/manager_combined.py`

6. **抽象层级系统**
   - `AbstractionGenerator`: 生成和管理抽象概念
   - 位置: `src/forest/abstraction/generator_combined.py`

7. **平衡系统**
   - `BalanceManager`: 实现自我平衡机制
   - 位置: `src/forest/balance/manager.py`

8. **评估系统**
   - `SystemEvaluator`: 评估系统状态并优化参数
   - 位置: `src/forest/evaluation/evaluator.py`

9. **获取系统**
   - `AcquisitionManager`: 主动获取外部知识
   - 位置: `src/forest/acquisition/manager.py`

10. **概念创新系统**
    - `ConceptSynthesizer`: 实现多种概念合成策略
    - 位置: `src/forest/innovation/synthesizer.py`

### 数据模型

主要数据模型包括：

1. **知识节点 (Node)**
   - 表示概念、实体、关键词等
   - 包含向量嵌入、摘要、内容和元数据
   - 支持生命周期状态和抽象层级

2. **关系边 (Edge)**
   - 连接知识节点
   - 定义节点间的关系类型和强度

3. **反思循环 (ReflectionCycle)**
   - 记录完整的反思过程和结果
   - 包含识别的缺口和执行的任务

4. **知识缺口 (KnowledgeGap)**
   - 表示知识结构中的问题
   - 包括覆盖度、深度、连接性等类型的缺口

5. **能量分配 (EnergyAllocation)**
   - 跟踪和管理系统资源分配
   - 实现能量恒定原则

## 技术栈

- **FastAPI**: 后端Web框架
- **MongoDB**: 数据存储及向量搜索
- **Redis**: 缓存和消息队列
- **WebSocket**: 实时通信
- **asyncio**: 异步处理
- **外部AI模型**: Claude、Gemini、Firecrawl等
- **MCP**: Model Context Protocol集成

## 设计模式应用

系统采用多种设计模式确保可维护性和扩展性：

1. **服务基类模式**: 所有服务继承自BaseService基类
2. **工厂模式**: 创建各种对象的通用工厂
3. **策略模式**: 封装不同算法和行为
4. **观察者模式**: 处理事件和通知
5. **装饰器模式**: 简化横切关注点
